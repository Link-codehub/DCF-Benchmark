# DCFEval：从空白工作簿构建 DCF 模型的 Agent 评测

DCFEval 用于评估财务建模 Agent 的完整工作过程。输入包括原始数据、业务假设和输出要求，模型需独立完成经营预测、历史聚合、估值计算和公式链接，并交付可重算、可追溯的工作簿。

核心评测链路为：**业务驱动 → 历史与预测 → FCFF / 三表 → 折现与终值 → 股权桥 → 活公式交付**。

以下**造题和 rubrics 生产基于我在一级投资买方和大模型后训练岗位实习的业务经验**，由于资源限制还未能优化到最好效果，后续将继续迭代

## 1. 结果与模型实测结果

`tasks/` 包含 **40 道 Harbor 题**：16 道基本题、12 道行业题、4 道多跳题、4 道开放预测题、4 道联网取数题。

以下为 frontier 模型实测结果。百分制按每题主需 3 分、次需 1 分计算；公式与模型工程类任一失败整类清零，其他类别按权重累计，再对已完成题目取平均。百分制相比通过率，也会考虑经营预测、可读性等主观判断的层面。

| 模型 | 样本数 | 百分制得分 | rule 条目通过率 | DCF 核心机制与公式通过率 |
|---|---:|---:|---:|---:|
| Kimi K3.1 Pro | 18 | **50.80** | 57.31% | 51.62% |
| DeepSeek V4 Pro | 14 | **43.43** | 51.13% | 45.04% |

本次主要由于 API 额度不足，只分别测评了 Kimi 的 18 道题和 DeepSeek 的 14 道题。逐题成绩见 `evaluation/RESULTS.md`。

## 2. 可扩量造题方案

造题由独立的外部 Agent 按 Prompt 和结构化 spec 完成，当前会话负责组合设计、协议、验收和评分。生产流程如下：

```text
DCF 基本能力多维度组合+其他考察维度
        ↓ 外部造题 Agent
结构化 spec + 原始事实与公开假设
        ↓ 程序生成
题面、公开输入、独立真值、活公式参考工作簿
        ↓ LLM按题挑选 rubric
题目适用性检查、参考验收、Harbor 题包
```

### 基本题

基本题将时间轴、历史口径、财务报表和输出结构交叉组合，同时题面直接给出业务背景、财年和估值要求：

- 时间：非自然财年、估值日在财年中间、残余期＋完整年度、实际天数、年中/期末折现；
- 历史：完整年度、半年、季度、半年＋桥接季度拼接 LTM，SBC 与非经常项规范化；
- 财务：营运资本期初口径、固定资产与无形资产滚动、现金税与 NOL、债务计划表；
- 输出：简版 DCF、三表＋DCF、分部 SOTP、风险调整管线、情景驱动经营模型、多方法估值与反推、债务计划表＋DCF。

### 行业经营驱动

行业题按行业事实构建预测，覆盖软件与订阅 SaaS、消费零售与连锁、制造与工业设备、医药与生物科技、医疗服务、银行与金融、保险、能源与资源、公用事业与基础设施、交通与物流、互联网平台与媒体、房地产、专业服务与外包、设备即服务与装机运维。

已落地的经营口径包括 ARR 净留存与新签、同店与新店、产能利用率、专利悬崖、平均生息资产与净息差、储量递减与开发资本开支、受监管资产基数、NOI/NAV、BOM 单耗与良率、患者漏斗与有限专利期。

### 多跳题、开放预测题与联网取数题

多跳题设置 3–4 次连续修改，包括重定基期、剥离分部、收购、融资与资本开支重排、营运资本口径改变和终值方法变化。每步保存快照，核验各步骤的事件依赖及最终模型。

开放预测题要求模型自行提出预测假设，并实现至少 5,000 条 Monte Carlo 路径。评分关注历史依据、论证一致性、模拟算术和分位数来源，不设置唯一的合理增长率。

联网取数题要求在限定的 SEC、公司 IR 和国债来源中取数并交叉验证，检查字段、期间、单位，以及模型公式对取数结果的实际引用。

## 3. Oracle 生产

由 spec 和程序输出的Oracle 用于验证题目、参考答案和评分器能否形成闭环。每道题按以下方式生成：

1. **公开输入与结构化 spec**：外部造题 Agent 按组合维度生成业务事实、期间、经营假设和输出键。答题环境只获得这些公开数据，不包含答案。
2. **独立真值**：生成器使用独立 Python 财务模型计算历史聚合、经营预测、FCFF、折现、终值、股权桥和输出键，写入 `tests/expected.json`。真值不从参考工作簿反读，也不由多个模型投票决定。
3. **活公式参考答案**：生成器构建 `solution/reference.xlsx`，关键输出为可追溯公式，而非把独立真值粘贴为常数。`solution/solve.sh` 将参考文件放到 Harbor 要求的输出位置，供 oracle 执行。
4. **隐藏扰动与专项真值**：题目预设至少两组经营、估值或股权桥输入变化，独立计算变化后的真值，用于检验参考公式是否真正联动。BOM、医药管线、敏感性网格等专项结构另设检查。
5. **负例**：空白工作簿、静态粘贴结果及题目专项错误必须被评分器拒绝，防止仅凭部分正确小项或结果碰巧一致而通过。
6. **实际验收**：用 LibreOffice 重算参考工作簿，与独立真值比对，再执行隐藏扰动和负例检查。最后在 Harbor 中运行 oracle，保存每题 reward。

开放预测题没有唯一的目标估值。其参考实现提供可复现的历史口径、模型与模拟器，评分侧重历史事实、公式自洽、逐路径重算和假设论证，而不是把自设预测压成唯一数值。

多跳题的每一步都分别生成该步输入、独立真值和参考快照，依次执行。前一步快照必须保留活公式，后续修改只能影响本步事件要求的依赖。

复现命令：

```bash
# 全部题包的 oracle 验证
python3 -u DCFEval/evaluation/run_oracle.py
python3 DCFEval/evaluation/summarize_oracle.py
```

当前 **40/40 道题的最新一次 Harbor oracle reward 均为 1.0**，证据见 `evaluation/ORACLE_VALIDATION.json`、`evaluation/ORACLE_VALIDATION.md` 和 `evaluation/oracle_jobs/`。

### 参考答案的迭代：

Agent 多轮对话＋模板＋Rubrics 生成参考答案，增强示例答案的专业性，可读性，并在开放问题等维度上取得更高分数

除程序生成的活公式 reference 外，本项目增加了一条参考表达层的迭代路径：

```text
公开输入 + 输出规范
        ↓
Agent 生成初版工作簿与 memo
        ↓
规则检查 + LLM/Agent 语义评审
        ↓
返回具体失败项及证据
        ↓
Agent 定点修改公式、模型结构或文字说明
        ↓
重新计算、重新评审并保留版本差异
```

尚未跑完全量，以下为 BC01 的示例。BC01 已形成一套 Agent 参考交付，包含：

- 专业参考工作簿：`tasks/BC01/solution/professional_reference.xlsx`；
- 估值说明：`tasks/BC01/solution/professional_memo.md`；
- 验证记录：`tasks/BC01/solution/professional_validation.json`。

这套示例用于比较“程序生成的基础参考”与“Agent 按 rubric 多轮打磨的专业参考”在以下方面的差别：

| 比较维度     | 基础参考             | Agent 多轮参考                                       |
| ------------ | -------------------- | ---------------------------------------------------- |
| 数值与公式   | 独立真值与活公式校验 | 同样必须通过独立真值与扰动校验                       |
| 建模过程呈现 | 以输出键和计算链为主 | 更强调历史、驱动、预测、估值桥的分区与引用关系       |
| memo         | 简要价值驱动与局限   | 进一步解释假设依据、行业口径、残余期处理和估值风险   |
| 可读性       | 满足程序检查         | 期间、项目、单位和结果标签更清楚，便于人工复核       |
| 开放题适应性 | 提供可复现示例       | 允许不同合理假设，但要求论证、模型和模拟结果相互一致 |

## 4. Rubrics 生产与评分

评分体系采用“统一 rubric 库 → 按题挑选 → 多方式判定 → 分类汇总”的流程，避免每道题临时编写宽泛、不可复现的评价标准。

### Rubric 库

统一库目前有 **200 条原子要求**，分为 9 类：

| 类别 | 主要检查内容 |
|---|---|
| 交付与来源完整性 | 交付文件、输出键、取数来源、来源字段、交叉验证及失败披露 |
| 多步状态与业务重构 | 快照保留、历史不被覆盖、事件修改范围及前后状态一致性 |
| 历史与会计口径 | 财年/LTM 聚合、SBC、非经常项、合同负债、现金收款和历史余额 |
| 经营预测 | 收入驱动、利润率、营运资本、长期资产、税务和行业经营指标 |
| 三表勾稽 | 资产负债配平、现金勾稽、留存收益及长期资产滚动 |
| DCF 与估值桥 | FCFF、折现期、终值、WACC、股权桥、稀释股数及每股价值 |
| 公式与模型工程 | 活公式、重算一致性、外部链接、输入扰动传导及敏感性网格 |
| 开放假设与模拟 | 历史依据、假设论证、模拟分布、相关性、逐路径计算与分位数 |
| 表达与专业可用性 | 单位、期间和项目标签、公式可读性、memo 的价值驱动与局限说明 |

库由既有方案的共用原子、开放预测评分项、当前题型新增要求，以及外部 benchmark 的抽象评分维度合并去重形成。每条 rubric 只判一个明确事项，并能依据交付证据判定 0/1。例如 FCFF 与折现期分开评价，取数正确与取数被公式实际引用分开评价，避免一个复合项同时包含多个无法独立判定的要求。

### 按题挑选

题目生成后，调用 Claude Opus 5.5，依据该题 spec、题面和适用条件，按类别从库中选择具体 rubric ID，并给出简短选择理由。

程序随后删除不存在或不适用于该题族的 ID，补齐该类题必须具备的项目，并按实际模块过滤误选项。例如，未启用三表时不选三表勾稽，未启用双资产池时不选无形资产，未要求 PPT/PDF 时不选展示材料一致性。原始选择与适用性修订均保留，便于复核本题为何需要对这些条目负责。

### 判定方式

| 方式 | 适用内容 | 证据形式 |
|---|---|---|
| Rule 程序判定 | 数值、历史聚合、公式、重算、输入扰动、取数映射、模拟算术 | 独立真值、LibreOffice 重算结果、公式依赖与结构化输出 |
| LLM 单项评审 | memo 中的价值驱动、行业因果链、再投资理由、局限披露 | 单项 rubric、题面、memo 与必要公开事实，逐项独立判 0/1 |
| Agent 小组评审 | 单位、期间和项目标签、工作簿结构、公式可读性、取数行为 | 同题一小组一次会话，使用工具读取工作簿并记录具体单元格或字段证据 |

语义评审不读取参考答案、隐藏真值或评分器，避免把“与答案接近”误认为主观论证合理。未执行或未返回有效结果的条目标为未评分，不自动算通过。

### 权重与汇总

主需权重 3，次需权重 1。每题先计算类别内得分，再换算为百分制。

主口径中，公式与模型工程类任一失败整类清零，防止静态结果或局部正确掩盖建模工程失败；其他类别按所选条目的权重累计。模型总分为已完成题目的算术平均，避免输出键较多的题主导最终分数。

同时报告两个通过率：

- **rule 条目通过率**：所有已执行 rule 条目的通过数 / 已执行 rule 条目总数；
- **DCF 核心机制与公式通过率**：经营预测、三表勾稽、DCF 与估值桥、公式与模型工程、开放模拟相关 rule 条目的通过率。

百分制反映综合建模质量，rule 通过率更直观地回答“计算和公式做对了多少”。

### 具体示例

- `05-DF`：折现期必须从估值日起按实际天数计量，并遵守年中/期末折现约定。
- `05-FCFF`：FCFF 从无杠杆税后 EBIT 出发，正确加回折旧摊销、扣除资本开支和营运资本增加。
- `06-RECALC`：LibreOffice 重算后，候选结果与独立真值一致。
- `06-PERTURB1/2`：修改经营、估值或股权桥输入后，下游结果按公式依赖正确传导。
- `W-USED`：取到的数据必须被模型公式实际使用，不能只在 Sources 页列出来源、在别处另填数值。
- `D-STEP-SNAPSHOT`：每一步均保存独立快照，缺任一步即失败。

完整库与逐题选择见 `generation/rubric_library/` 和各题 `rubric.json`，原始判定见 `evaluation/scores/`，语义评审见 `evaluation/judges/`。

## 4. 方案迭代

早期探索中，完整假设与明确公式容易使模型接近满分，难以区分真实建模能力。后续采用现在类似的基本方案，然后逐步扩充各个维度的覆盖范围，迭代出题方式和题面设计。

从多次模型实评结果完善 rubrics 库。

后续方案进一步明确工作边界：基本题负责场景与时间轴，三表题补足勾稽和跨表依赖，行业题承载行业经营机制，多跳题负责连续修改，开放预测题单列假设与 Monte Carlo。多维组合逐步形成当前分类。

## 5. 失败案例分析

32 个已评样本的失败主要集中在三类基础能力：

1. **经营预测链条不完整或驱动口径错误。** 该类失败共 107 项，涉及收入驱动、利润率、营运资本、长期资产和行业经营指标。模型往往先搭出估值框架，再用增长率或固定比例代替业务事实推导。
2. **估值计算存在系统性偏差。** DCF 与估值桥失败共 98 项。折现期 `05-DF` 检查是否从估值日起按实际天数计算折现年数，并遵守题目规定的年中或期末折现惯例；FCFF `05-FCFF` 检查是否从无杠杆税后 EBIT 出发，正确加回折旧摊销、扣除资本开支和营运资本增加。每股价值和股权桥也是高频失分点。
3. **公式依赖和可重算性不足。** 公式与模型工程失败共 78 项。`06-RECALC` 指用 LibreOffice 重新计算候选工作簿后，结果应与独立真值一致，该项失败 19 次；`06-PERTURB1/2` 指改变一组经营、估值或股权桥输入后，下游输出应按公式依赖同步更新，两组检查各失败 18 次。

两模型的差异主要体现在失败分布：Kimi 更集中于重算和扰动传导，DeepSeek 更集中于折现期、FCFF 和股权桥。以下为具体案例，用于说明上述共性问题的实际表现。

### 残余期口径

A01 题目将整年的新签 ARR 和净留存直接用于估值日后的残余段，导致收入、利润率、资本开支、NWC、FCFF 和估值连续偏离。类似问题也出现在零售、医药和公用事业题中。

错误根源在于混淆年度流量、期末余额和估值日后活动比例。期初 NWC 与期末资产余额不能按残期比例缩放，收入与资本开支需按题目约定处理。

### 行业经营口径

A02  题目的同店与新店驱动、A04 的专利悬崖、A05 的净息差与股权现金流、A07 的受监管资产基数均出现核心口径错误。模型能够生成估值框架，但未能始终正确地将业务事实纳入预测。

### 折现、FCFF、NWC 与公式传导

高频失败集中在 `05-DF`、`05-FCFF`、`03-NWC`、`06-RECALC` 和两组输入扰动，主要涉及：

- 年中/期末折现惯例叠加错误；
- NWC 期初余额选择错误；
- 资本开支或无形资产重复扣减；
- 现金、租赁等股权桥项目漏计；
- 修改输入后结果未按公式依赖传导。

### 联网取数与开放预测

DeepSeek W01 存在多个 SEC 历史期间与国债日期错误，且未正确引用来源；Kimi 在同题通过规则检查。W02/W03 分别暴露来源映射、交叉验证、FCFF 和折现问题。

开放预测中，Kimi 出现折现与模拟重算错误；DeepSeek 还出现历史收入、EBIT、EPS 和估值桥错误。开放假设仍需满足历史事实、估值机制和模拟算术的约束。

完整逐题判定见 `evaluation/RESULTS.md`，原始分数、judge 结果与交付索引保存在 `evaluation/`。
